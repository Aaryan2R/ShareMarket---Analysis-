Goal of this copy
-----------------
This folder is a full improved copy of the original Share_Market--Analysis project. The original project is separate. This copy keeps the active data and assistant.db, but has cleaner code, a working venv, normalized CSVs, RAG retrieval, an agent-router layer, and tests.

Active entrypoints
------------------
1. ai_trading_assistant_ui.py
   Tkinter desktop assistant.
   Uses main-thread queue for UI updates from background work.
   Uses IntelligenceDB, Orchestrator, RagEngine, LLMClient, and AgentRouter.
   Shows an AI connected/offline indicator.

2. main.py
   CLI runner.
   Options:
   --rank-only
   --normalize-csvs
   --force-strategy

Important modules
-----------------
core/config.py
  Central paths and environment variables.

core/database.py
  Unified SQLite gateway for assistant.db.
  Tables: companies, intelligence_packets, messages, snapshots.

core/company_match.py
  Alias and fuzzy matching for TCS, INFY, Reliance, Asian Paints, etc.

core/market_data.py
  Reads and normalizes data/raw/<Company>/prices/daily/daily.csv.
  Drops invalid ticker rows after CSV headers.

core/orchestrator.py
  Lazy market intelligence pipeline.
  Builds packets from local CSVs.
  Computes extended technical metrics: RSI, MACD, Bollinger Bands, support/resistance, trend.
  Loads FinBERT only when live sentiment is enabled and sentiment is requested.
  Fetches market regime only when strategy rebuild needs it.

core/rag_engine.py
  Builds retrieval documents from company rows, cached packets, price metadata, and company universe.
  The old deterministic_answer path is removed. Retrieval now feeds the agent/tool loop.

core/llm_client.py
  Calls local OpenAI-compatible endpoint.
  Default endpoint: http://localhost:1234/v1/chat/completions.
  Default model: meta-llama-3.1-8b-instruct.
  Includes reachability check, retry, JSON tool-call parsing, and streaming support.

core/agent_router.py
  Agentic loop.
  If the LLM is reachable, the LLM can emit a JSON tool call, the app executes it, then the LLM answers from the result.
  If the LLM is not reachable, it falls back to data-only answers for rankings/company packet data.

core/tools.py
  Local tools exposed to the agent:
  list_companies, add_company, remove_company, set_nse_symbol, get_company_status,
  get_company_analysis, rank_companies, compare_companies, compute_win_rate,
  show_chart, refresh_all, normalize_csvs, fetch_prices, search_knowledge.

core/prompts.py
  Prompt protocol for local models that may not support native function calling.
  Tool calls are requested as JSON inside a json code fence.

tests/
  Pytest suite for company matching, DB/packet roundtrip, RAG retrieval, tool registry, and CSV normalization.

Design decisions
----------------
The app remains Python/Tkinter to preserve the original user experience.
The archived engine stays under archive_old_engine for reference only.
The active DB is assistant.db. Do not reintroduce trading_system.db as a second active database.
RAG is now context retrieval for the agent loop rather than deterministic final answering.
If the local LLM is unavailable, AgentRouter falls back to raw local data for common tasks.
For full natural-language AI answers and tool planning, LM Studio or another OpenAI-compatible local server must be running.

Known notes
-----------
Some source comments/UI strings contain mojibake-looking characters caused by prior encoding conversions. The app still imports and tests pass. If console checks print symbols on Windows, set PYTHONIOENCODING=utf-8.
